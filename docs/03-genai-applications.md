## 📖 核心概念

### 从"训练模型"到"使用模型"

阶段二你懂了模型怎么来的。这一阶段起，你**不用再自己训练**——直接用别人训练好的强大模型（GPT-4、Claude、Llama、Qwen 等），通过 API 或本地部署来使用。

### Prompt 工程：和模型对话的艺术

同样一个模型，Prompt 写得好不好，输出天差地别。核心技巧：

| 技巧 | 说明 | 例子 |
|---|---|---|
| **清晰指令** | 明确告诉模型要做什么、输出什么格式 | "用 3 个要点总结，每点不超过 20 字" |
| **角色扮演** | 给模型设定身份 | "你是一位资深 Python 工程师…" |
| **Few-shot** | 给几个示例让模型照做 | 给 2-3 个"输入→输出"样例 |
| **思维链 (CoT)** | 让模型"一步步想" | "让我们一步步推理…" |
| **结构化输出** | 要求返回 JSON 等格式 | "以 JSON 返回，字段为 name/age" |

### 大模型的能力边界（要心里有数）

- ✅ 擅长：语言理解、生成、总结、翻译、代码、创意
- ⚠️ 短板：会**幻觉**（编造事实）、不知道训练截止后的新知识、不擅长精确计算
- 👉 这些短板正是阶段四（RAG / 工具调用）要解决的

## 📚 核心知识精讲（微软 GenAI 课 + Prompt 指南提炼）

> 微软 generative-ai-for-beginners 有 21 节课，Prompt-Engineering-Guide 更是长篇。我把其中**做应用真正用得上的核心**抽出来放这里，掌握这些你就能动手了。

### 1. 大模型 API 的心智模型：一切都是「一段对话」

无论 OpenAI、Claude 还是国产模型，调用方式都归一为一个 `messages` 列表，三种角色：

| 角色 | 作用 | 举例 |
|---|---|---|
| `system` | 设定模型的身份/规则，全程生效 | "你是严谨的医学助手，不确定就说不知道" |
| `user` | 用户说的话 | "帮我总结这段文字" |
| `assistant` | 模型之前的回复（多轮对话时带上，模型才有记忆） | （上一轮模型的回答） |

**关键参数**（做应用必调）：
- **temperature**：0~2，越高越有创意也越"飘"；要稳定/事实性任务调低（0~0.3），要创意调高（0.8+）。
- **max_tokens**：限制回复长度，控成本。
- **top_p**：另一种控制随机性的方式，一般和 temperature 二选一调。
- **stream**：开启流式，逐字返回（做聊天界面的打字机效果靠它）。

> **Token 概念**：模型按 token（约等于 0.75 个英文单词 / 1~2 个汉字）计费和计长度。上下文窗口（如 128k tokens）= 一次能"记住"的最大文本量，超了就得裁剪或用 RAG（阶段四）。

### 2. Prompt 工程六大核心技巧（背下来，天天用）

这是 Prompt-Engineering-Guide 的精华浓缩：

**① 清晰具体**——把要求、格式、约束一次说清。
> ❌ "总结一下" → ✅ "用 3 个要点总结以下文章，每点不超过 20 字，用中文"

**② 角色设定 (Role Prompting)**——给模型一个身份，输出立刻专业。
> "你是有 10 年经验的儿科医生，用家长能懂的话解释……"

**③ Few-shot（给例子）**——给 2~3 个"输入→输出"范例，模型照葫芦画瓢，格式和风格立刻对齐。
```
输入：这家餐厅太棒了！ → 情感：正面
输入：等了一小时菜还没上。 → 情感：负面
输入：环境一般般吧。 → 情感：
```

**④ 思维链 CoT (Chain-of-Thought)**——让模型"一步步想"，复杂推理/数学题正确率大幅提升。
> 加一句"让我们一步一步推理"或"先分析再给结论"。

**⑤ 结构化输出**——要求返回 JSON/表格，方便程序解析。
> "以 JSON 返回，字段：{name, age, summary}，不要多余文字。"

**⑥ 给模型"退路"**——允许它说"不知道"，是治幻觉的最简单一招。
> "如果资料里没有答案，请回答'我不确定'，不要编造。"

### 3. 治「幻觉」的实战三招

课程反复强调，大模型会一本正经胡说。应用层能做的：
1. **降 temperature**：事实类任务调到 0~0.3。
2. **给上下文**：把参考资料塞进 Prompt（这就是 RAG 的雏形，阶段四展开）。
3. **要求引用来源 + 允许说不知道**：逼模型"有据才答"。

### 4. 什么时候该微调，什么时候只需 Prompt / RAG？

微软课里一个重要判断（新手常搞反）：

```
先试 Prompt 工程  ──能解决？──→  用它，最省事
      │ 不行
      ▼
知识不够/要私有数据 → 用 RAG（阶段四）喂资料，别急着微调
      │ 还不行
      ▼
要改变"风格/行为/格式" → 才考虑微调(Fine-tuning)
```

> 口诀：**能 Prompt 不 RAG，能 RAG 不微调**。微调成本最高，是最后手段。

### 5. 语义搜索 & Embedding（承上启下到阶段四）

课程后半引入的关键概念，是 RAG 的基础：
- 把文本用 **Embedding 模型**转成向量，语义相近 → 向量距离近。
- "语义搜索"= 把查询也转成向量，找距离最近的内容——即使用词不同也能匹配（搜"怎么退货"能命中"退款流程"）。
- 这就是阶段四 RAG 的检索环节，先在这里建立概念。

```python
# 最小可用的大模型调用（以 OpenAI 兼容接口为例）
from openai import OpenAI

client = OpenAI(base_url="你的API地址", api_key="你的key")
resp = client.chat.completions.create(
    model="模型名",
    messages=[
        {"role": "system", "content": "你是一个乐于助人的助手"},
        {"role": "user", "content": "用一句话解释什么是注意力机制"}
    ]
)
print(resp.choices[0].message.content)
```
